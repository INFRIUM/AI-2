### 1. 4절 협의 요청에 대한 답

| 요청 | AI② 답 |
|---|---|
| `score_ratio`와 `ai1_status`만으로 위험도를 정하지 않음 | 동의합니다. 같은 점수라도 모델마다 의미가 다르므로, 위험점수·등급 기준은 모델별로 따로 정합니다 (문서 5–6절) |
| 모델별 위험도 기준은 AI②, 최종 출력 형식만 통일 | 동의합니다. 출력은 위험점수 0–100, 4단계 등급, 판정 보류로 통일합니다 (문서 8절) |
| 적용 방식 ①–④, 원 교량·HW 검증 구분 | 동의합니다. AI② 문서 9절에 같은 구분을 반영했습니다 |
| HW 결과를 정상 오경보와 손상 탐지로 나눠 보고 | 동의합니다. AI② 위험도도 같은 두 칸으로 보고합니다 |

### 2. 전달 열: 제안하신 8개 + 추가 요청

제안하신 `ai1_model`, `ai1_model_version`, `ai1_apply_mode`, `ai1_baseline_id`, `anomaly_score`, `ai1_threshold`, `score_ratio`, `ai1_status`는 그대로 받겠습니다. 아래를 추가로 부탁드립니다.

| 추가 열 (안) | 필요한 이유 |
|---|---|
| `experiment_id`, `window_start_us` | AI② 결과와 Window를 짝지음 |
| `hold`, `hold_reason` | 판정 보류 여부와 이유를 등급 사유에 그대로 적음 |
| `top_sensor` | 가장 크게 벗어난 센서를 등급 사유에 적음 |
| 정상 기준 측정 날짜·기간 (`ai1_baseline_id`로 찾을 수 있으면 별도 표 1개) | 평가 Window가 기준에 쓰지 않은 날인지 확인 |
| 모델이 쓴 지표값 (A: AR(5) 계수 또는 MSD 값) | AI②가 정상 대비 변화량을 직접 계산할 때 필요 |

열 이름은 AI① 쪽에 맞추셔도 됩니다.
