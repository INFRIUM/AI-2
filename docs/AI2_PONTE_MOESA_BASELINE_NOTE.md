# Ponte Moesa: 정상 상태가 없어 정상 판별·등급 평가에서 제외

작성일: 2026-11-20 (AI① 확인 반영, 최종 결정) · 관련: #15, #19, #21, PR #22 · 대상: Ponte Moesa (Box, `AI1-public-1.1`, `AI1-public-1.3`)

## 1. 결정

> **Ponte Moesa에는 정상이라고 판별할 수 있는 데이터가 없다. 그래서 정상/이상 판별, 위험 등급, 오경보 평가에서 제외한다.**
> 성능이 나빠서가 아니라 **정상 기준 데이터가 없어서**다. Box의 정상·등급 평가는 Z24로만 한다.

| 항목 | 결정 |
|---|---|
| 정상 상태 | **없음.** 첫 측정(DS0)부터 철근이 노출된 손상 상태 |
| DS2 (철근 I·II·III 노출) | 손상 상태. 손상 기록상 절대 등급은 **주의**. 정상으로 쓰지 않음 |
| 정상/이상 판별, 위험 등급, 오경보율 | **제외.** 정상 기준이 없어 정의할 수 없음 |
| 남는 용도 | 손상 진행 순서 확인(DS2 → DS3 → DS5 → DS7로 갈수록 지표가 커지는가)의 **개발용 참고** |
| Box 정상·등급 평가 | **Z24** (손상 시험 전 상시 계측) |

## 2. 근거 (AI① 원본 확인, #15 댓글 7030462384)

| 상태 | 논문 표 1 | 시작 시각 (논문 그림 6) |
|---|---|---|
| DS0 | 철근 I·II 노출 | 11/26 10:32 |
| DS1 | 위치 II 콘크리트 추가 제거 | 11/26 15:50 |
| DS2 | 철근 I·II·III 노출 | 11/26 16:43 |

- 공식 목록의 첫 측정 AMB_1부터 DS0이다. **데이터셋 전체에 손상 없는 측정이 없다.**
- 논문(Garcia-Ramonda et al. 2025)은 "setup S5 was implemented after the initial damage was carried out, thus DS_2 is herein considered as the reference state"라며 DS2를 기준으로 쓴다. 센서 설치 시점 때문이지 손상이 없어서가 아니다.
- AI①이 제외했던 AMB_2–6은 공식 목록과 논문 그림의 상태가 한 단계씩 달라 뺀 것이고, 모두 DS0·DS1(손상 상태)이다.

## 3. 무효 처리한 결과

DS2를 정상으로 놓고 계산한 결과는 정상/이상 평가로서 **무효**다.

| 결과 | 처리 | 위치 |
|---|---|---|
| v1 Box 검증 (사전 등록, 1회) | 고정된 결과라 숫자와 사전 등록서는 그대로 두고, "정상/이상 평가로는 무효"를 결과 문서에 덧붙임 | `docs/AI2_PUBLIC_GRADE_RESULT_v1.md` 8절 |
| 규칙 v3 Box 판정 | **판정 대상에서 제외.** 결과 문서의 Box 절을 제외 안내로 바꾸고, Window별 결과 파일(`ponte_moesa_*_grades.csv`)을 지움. 코드(`grade_v3.py`)에서도 판정 대상에서 뺌 | `docs/AI2_GRADE_RESULT_v3.md` |
| XGBoost Box 학습 건 `ponte_moesa_20261120_e5999bb0`, `_cac837b7` | 학습 건 목록의 상태를 **"무효: 데이터셋에 정상 없음"**으로 바꿈. 기록 추적용으로만 남김 | `results/public_grade/xgb_performance/` |

참고로 XGBoost Box 실험에서는 모델이 "굴착기 작업 중인 11/27 측정(AMB_18) = 정상"을 배워, 가장 심한 손상 DS7을 정상처럼 판정했다(DS7 묶음 AUC 0.10). 정상이 없는 데이터로 정상을 학습하면 이런 일이 생긴다.
