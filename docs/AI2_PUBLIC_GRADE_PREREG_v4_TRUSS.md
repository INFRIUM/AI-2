## 0. 목적과 고정 시점

- Truss는 HBTA·Old ADA로 판정과 내부 평가까지 마쳤지만, 아직 보지 않은 데이터가 없어 **검증을 하지 못했다.** 이 문서는 신청 없이 바로 받을 수 있는 실제 구조물 데이터 두 개로 **규칙 v3(이상의 확실성)를 바꾸지 않고 한 번 검증**하는 방법을 고정한다.
- 이 문서와 평가 코드를 커밋하고 Push한 뒤에 AI①이 Window·열화본 처리를 한다. 커밋 시각과 이 문서의 SHA-256이 고정 시점의 증거이고, 실행 결과에 이 문서의 SHA-256을 기록한다.
- 결과를 본 뒤 규칙을 바꾸지 않는다. 오류가 발견되면 v5로 새로 등록하고 v4 결과와 함께 보고하며 "결과 열람 후 변경"을 표시한다.
- 평가는 데이터마다 1회만 실행한다.

## 1. 결과 표시 방식 (먼저 고정)

| 데이터 | 통과했을 때 쓸 수 있는 표현 | 쓸 수 없는 표현 |
|---|---|---|
| LUMO (주 평가) | "실제 트러스 구조물(격자 철탑)의 바람 상시 진동 조건에서, 정상 기준과 다른 계절의 정상 기간을 포함해 정상/이상 구분 통과" | "트러스교 검증 통과" (교량이 아님) |
| Vänersborg (보조) | "개폐식 트러스교의 개폐 이벤트 조건에서 실제 파단 전후 구분 통과" | 교통 진동 조건의 트러스교 검증 |
| 공통 | 열화본(HW 센서 조건) 기준 | 원본 결과를 성능으로 주장 |

- 어느 결과든 **"교통 진동 조건의 트러스교 손상 탐지는 검증 데이터 없음"**을 함께 표시한다.
- 통과해도 API의 `risk_score`, `risk_level`은 연결하지 않는다. 공개 데이터 통과는 HW 실측 검증을 대신하지 않는다.
- **4단계 등급의 정확도는 검증하지 않는다.** 규칙 v3 등급은 "정상 기준과 다르다는 확실성"이고, 이 문서의 통과 조건은 정상/이상 구분(경고 이상 = 이상)이다. 등급 분포는 서술만 한다.

## 3. 처리 (AI①, `AI1-public-1.4`)

공통 규칙은 `AI1-public-1.1`과 같다: 열화 순서 잡음 → 14bit 양자화 → ±2g 범위 제한 → 2–25Hz 4차 Butterworth 대역 통과(양방향) → Feature. 잡음은 LIS2DW12 고성능·저잡음(90µg/√Hz), 시드 `20261109`. 원본도 같은 필터·Feature를 적용한다(열화만 하지 않음).

| 항목 | LUMO | Vänersborg |
|---|---|---|
| acc01 | ML5 (높이 5.00m) | A1 (개폐 경간 약 1/3 지점, 수직) |
| acc02 | ML1 (높이 8.95m, 꼭대기) | A5 (균형추 트러스 끝, 수직, 균열에 가장 가까움) |
| 축 | x, y (수평) | z (닫힌 상태 기준 수직) |
| 단위 | g → m/s² (×9.80665) | m/s² 그대로 |
| 샘플링 | **1651.61Hz → 200Hz로 낮춘 뒤 열화.** 블록마다 FFT 재표본화(`scipy.signal.resample`, 100Hz 위 성분 제거). 블록 양 끝을 5초씩 거울 반사(reflect)로 덧댄 뒤 재표본화하고 덧댄 부분을 잘라내, 블록당 round(990600 × 200 / 1651.61) = 119956 샘플. 시간축 = 블록 시작 시각(`Dat.Time`, UTC) + k/200초. 순서: g → m/s² → 200Hz → 원본 파일 / 같은 신호에 열화 → 열화본 파일 | 200Hz 그대로 |
| 중력 | 수평축이라 더하지 않음 | **경사계 각도 θ로 g·cos θ를 더한 상태로 양자화·범위 제한 후 다시 뺌** (기존 수직축 +1g 규칙을 회전하는 교량에 맞게 확장). θ는 같은 행의 `ch_25` 값(가속도와 같은 DAQ, 200Hz). 경사계 빈 행은 앞뒤 유효 값으로 선형 보간하고, 보간할 수 없는 이벤트 시작·끝만 θ = 0(1g). 이벤트별 빈 행 수와 처리를 기록 |
| Window | 60초, 30초 이동. 10분 블록 안에서만, 블록 시작부터 자름. 블록이 599.78초(990600 샘플)라 **블록당 18개** | 10.24초, 겹침 없음. 이벤트 파일 시작부터 끝까지 |
| 보류 | 열화본에서 acc01 x·y, acc02 x·y **4개 채널 중 하나라도** 보류면 `hold_main` = True. 보류된 채널의 특징과 그 채널을 쓰는 TAC는 빈 값 (1.1과 같음) | acc01 z, acc02 z 중 하나라도 보류면 `hold_main` = True |
| 보류 기준 | 1.1의 `deg_200Hz` 기준 (RMS 0.0057m/s²) 그대로 | 같음 |
| Feature | AR(5) 계수 (`acc0{1,2}_ar{1..5}_{x,y}`), `tac_a_b_x`, `tac_a_b_y` (a = acc01, b = acc02), 1.1과 같은 통계·대역 | AR(5) z, `tac_a_b_z`, 통계·대역 |
| TAC 기준 스펙트럼 | `ai1_split` = `train` Window(4절 B1)의 평균 스펙트럼 비 (1.1과 같은 방법, Window 1개 단위) | 같음 (5절 E1) |
| 표시 | `label_status` = `확인용`, `model_version` = `AI1-public-1.4`, `damage_stage` = 4절·5절 이름, `source_record` = 블록 파일 이름(LUMO) 또는 이벤트 파일 이름(Vänersborg), `cv_group` = 구간 이름 | 같음 |
| 파일 | `lumo_anomaly_results_raw.csv`, `lumo_anomaly_results_deg.csv` (+ `column_guide.csv`, `experiment_labels.csv`, `sensor_info.csv`, `data_provenance.json`) | `vanersborg_anomaly_results_{raw,deg}.csv` (+ 같은 부속 파일) |
| 시각 | `window_start_us` = **UTC 기준 Unix 시각(µs)** (블록·이벤트 안 경과 시간이 아님) | 같음 |

- 2–25Hz 대역은 HW 처리와 같게 둔다. 데이터를 보고 바꾸지 않는다. 철탑의 고유 진동수가 이 대역 밖에 있으면 그만큼 불리하며, 이는 한계로 보고한다(10절).
- AI① v1 모델의 판정(`prediction`)은 만들지 않아도 된다. 만든다면 참고로만 보고한다.
- **LUMO 받기·보관 (AI① 7074615611):** 필요한 블록만 부분 다운로드(HTTP Range)하고, 사용 채널 4개(`accel05x`, `accel05y`, `accel01x`, `accel01y`)만 꺼내 변환한 뒤 블록 파일은 지운다. 블록 파일 이름, ZIP 안 위치, 메타 라벨, CRC32 확인 결과(블록을 통째로 받은 경우) 또는 받은 바이트 범위(채널만 받은 경우)를 `data_provenance.json`에 기록한다. 쓰는 채널이 같으므로 결과는 블록 전체를 받은 경우와 같다.
- 고정 전 구조 확인(ZIP 목록, 블록 1개의 HDF5 구조)은 31개 구간 밖의 블록으로, 값을 읽지 않고 한다.

## 4. LUMO 구간 선택과 역할

전체(약 12개월, 한 달 약 290GB)를 처리하지 않고, **9시간 구간**(10분 블록 최대 54개)을 미리 정한 규칙으로 고른다. 구간에 드는 블록 = 블록 끝 시각이 (시작, 시작 + 9시간]에 있고, 라벨이 그 상태(정상 2, 손상 3)인 블록.

**구간 시작 시각 규칙 (UTC)**

- 정상 기준 기간 N1(2020-08-01 00:02부터 10-09 08:40까지): 아래 표처럼 11일 간격, 시작 시각 00:00과 12:00을 번갈아 6개 + 같은 계절 확인용 1개.
- 그 밖의 상태 구간 [s, e]: 초반 구간 A = s 날짜 + 2일의 00:00, 후반 구간 B = e 날짜 − 1일의 12:00. 상태가 바뀐 직후 하루와 바뀌기 직전 반나절을 피하고, 하루 중 다른 시간대를 하나씩 넣기 위해서다.
- **대체 규칙:** 구간에 쓸 수 있는 블록이 27개(절반) 미만이면 A와 N1 구간은 하루 뒤로, B는 하루 앞으로 옮긴다(최대 3번). 그래도 부족하면 있는 블록만 쓰고 기록한다. 평가 코드는 각 구간의 Window가 원래 구간 또는 허용된 대체 구간 안에 있는지 확인하고, 옮긴 날 수를 결과에 기록한다.
- **구간 이름(`cv_group`):** N1은 `N1_B1_0803`, `N1_B1_0905`, `N1_B2_0814`, `N1_B2_0825`, `N1_B2_0916`, `N1_B2_0927`, `N1_S_1006`. 그 밖은 `<상태>_A`, `<상태>_B` (예: `N2_A`, `N3_B`, `DAM6_111_A`, `DAM3_010_B`). 정상 N2–N7의 `damage_stage`는 `UDS`.

| 지표 | LUMO | Vänersborg |
|---|---|---|
| AR 진동 특성 거리 d = √((a − μ)ᵀ Σ⁺ (a − μ)) | a = 열화본 AR(5) 계수 20개 (acc01·acc02 × x·y). μ, Σ = B1의 판정 가능 Window 평균·공분산, Σ⁺ = `numpy.linalg.pinv` | a = AR(5) z 계수 10개. μ, Σ = E1 |
| 전달 관계 1-TAC | (`tac_a_b_x` + `tac_a_b_y`) / 2 | `tac_a_b_z` |

- 판정 사유에는 센서별 AR 거리(같은 방법, 그 센서의 계수만)를 함께 적는다. 센서별 값은 등급 계산에 쓰지 않는다(규칙 v3 3절).
- **경계:** 지표마다 정상 기준(B2 또는 E2)의 판정 가능 Window로 p95(`numpy.percentile`, linear)와 최댓값을 정한다.
- **지표 수준:** 0 = p95 이하, 1 = p95 초과, 2 = 최댓값 초과.
- **Window 수준 E** = 지표 수준의 최댓값. **지속 수준 S** = 같은 구간(LUMO: 같은 10분 블록, Vänersborg: 같은 이벤트) 안에서 시작 시각이 Window 이동 간격(30초, 10.24초)만큼씩 연속한 최근 3개 Window의 E 중 두 번째로 큰 값.
- **등급:** 위험 S = 2, 경고 S ≥ 1, 주의 E ≥ 1이고 S < 1 또는 S 없음, 정상 E = 0, 판정 보류 `hold_main`.
- 코드는 `src/public_grade/grade_v3.py`의 `bounds`, `level`, `sustained`, `grade_sequential`, `reason`을 그대로 쓴다.

## 7. 통과 조건 (열화본)

**판정 Window** = 보류가 아니고 S가 있는 Window. 블록·이벤트의 처음 두 Window처럼 S가 없는 Window는 "판정 불가"로 따로 세고 비율에서 뺀다(v2와 같은 방식). **이상 = 경고 또는 위험.**

| 데이터 | # | 조건 | 대상 |
|---|---|---|---|
| LUMO | 1 | 오경보율 ≤ 5% | 정상 N2–N7 구간 12개의 판정 Window 합산 중 이상 비율 |
| LUMO | 2 | 위험 탐지율 ≥ 95% | DAM6_111, DAM4_111, DAM3_111 구간 6개의 판정 Window 합산 중 이상 비율 |
| Vänersborg | 3 | 오경보율 ≤ 5% | 파단 전 41–57번째 이벤트의 판정 Window 합산 |
| Vänersborg | 4 | 위험 탐지율 ≥ 95% | 파단 후 6개 이벤트의 판정 Window 합산 |

- LUMO는 1·2를 모두 통과해야 통과, Vänersborg는 3·4를 모두 통과해야 통과다. 두 데이터는 따로 판정한다.
- **잠정 표시:** 어느 조건이든 판정 Window가 200개 미만이면 그 데이터의 결과를 잠정으로 표시한다.
- **같이 보고:** 구간·이벤트·상태별 이상 비율과 등급 분포(정상/주의/경고/위험), 보류 수, 판정 불가 수, 대체 규칙 적용 여부.

**통과하지 못했을 때**

| 실패 | 기록 |
|---|---|
| LUMO 1 실패 | 정상 기준(여름 N1)과 다른 계절·기간의 정상 변동을 규칙 v3 경계가 담지 못함. 8.1절로 계절별 오경보를 기록 |
| LUMO 2 실패 | 열화본 지표가 큰 손상을 정상 변동과 구분하지 못함. 8.2절 원본 비교로 원인 기록 |
| Vänersborg 실패 | 같은 방식으로 기록 |
| 공통 | 지표, 경계, 구간, 연속 규칙을 결과를 보고 다시 고르지 않는다. Truss 결론 문서에 결과를 추가하고 "검증 아님" 표시를 유지한다 |

## 10. 함께 보고할 한계

- **LUMO는 교량이 아니다.** 높이를 경간처럼 보고 센서를 대응시켰다. 진동원도 바람이라 교통 진동과 다르다.
- **수직축 없음 (LUMO).** HW의 주 판정 축(수직)과 같은 조건이 아니다.
- **대역 2–25Hz 고정.** 철탑의 주요 진동이 이 대역 밖에 있으면 불리하다. 데이터를 보고 바꾸지 않았다.
- **샘플링 변환 (LUMO).** 원본 1651.61Hz를 200Hz로 낮췄다. HW 출력 속도에 맞춘 것이다.
- **Vänersborg는 개폐 이벤트다.** 센서 축이 교량과 함께 회전하고, 경간 중앙 센서가 없으며, 파단 후 이벤트가 6개(이틀)뿐이다. 오경보 확인 이벤트도 파단 직전 약 1주에 몰려 있다.
- **측정 단위 독립성.** LUMO 상태 구간은 상태마다 한 번(손상 장치 설치 기간)이라, 상태 차이와 시기(계절) 차이가 섞인다. 같은 계절 오경보(8.1절)로 일부만 구분할 수 있다.
- **구간 선택.** 전체가 아닌 31개 구간(약 279시간)만 쓴다. 구간은 값을 보지 않고 규칙으로 정했다.
