# AI② 위험 등급 규칙 v3 (A안: 이상의 확실성)

작성일: 2026-11-19 · 관련: Issue #18, #15 · 코드: `src/public_grade/grade_v3.py` · 이전: 등급 설계 v0(PR #12), 사전 등록 v1(#13), v2 Truss(#16)

## 0. 이 규칙을 만든 이유

- v1(손상 정도 4단계)은 Box·Truss 모두 등급 순서와 정상/이상 구분을 통과하지 못했고, v2 Truss(스윕 가진)도 위험 탐지 0%였다.
- 그래도 AI②는 AI①이 준 실제 데이터셋 전체에 등급을 판정해야 한다. 그래서 **손상 라벨 없이 정상 데이터만으로 경계를 정하는** 규칙을 쓴다(등급 대안 A안).
- **등급의 뜻이 바뀐다.** v3 등급은 "손상이 얼마나 심한가"가 아니라 **"이 Window가 정상 기준과 다르다는 것이 얼마나 확실한가"**다.

## 1. 검증 상태

- AI① 공개 데이터(`AI1-public-1.1`, `1.2`, `1.2-dev`)는 v1·v2 평가와 탐색에서 **이미 모두 봤다.** 이 규칙으로 낸 등급은 모두 **"이미 본 데이터로 판정, 검증 아님"**으로 표시한다.
- 손상 라벨은 경계를 정하는 데 쓰지 않고, 결과를 상태별로 나눠 보이는 데만 쓴다.
- 검증은 아직 보지 않은 실제 데이터(Z24)로 따로 사전 등록해서 한다.
- API의 `risk_score`, `risk_level`에는 연결하지 않는다(인수인계서 금지 사항).

## 2. 경계

지표마다 **정상 기준 Window**(정상 상태, 판정 보류 제외)로 두 경계를 정한다.

| 경계 | 정의 |
|---|---|
| p95 | 정상 기준 값의 95번째 백분위수 (`numpy.percentile`, linear) |
| 정상 최댓값 | 정상 기준 값의 최댓값 |

Window마다 지표 수준을 매긴다: 0 = p95 이하, 1 = p95 초과, 2 = 정상 최댓값 초과. 값이 없으면 그 지표는 빼고, 모든 지표가 없으면 "판정 불가"다.

## 3. 등급

**연속 측정 데이터 (Box, HBTA NM·SM)**

- Window 수준 E = 지표 수준 중 가장 큰 값
- 지속 수준 S = 연속한 최근 Window 3개(t−2, t−1, t)의 E 중 **두 번째로 큰 값** (3개 중 2개 이상이 도달한 수준). 앞 Window 2개가 없거나 연속하지 않으면 S 없음

| 등급 | 조건 |
|---|---|
| 정상 | E = 0 |
| 주의 | E ≥ 1, S < 1 또는 S 없음 (잠깐 벗어남) |
| 경고 | S ≥ 1 (p95 초과가 3개 중 2개 이상) |
| 위험 | S = 2 (정상 최댓값 초과가 3개 중 2개 이상) |
| 판정 보류 | 주 지표 판정 보류 (진동이 잡음 수준) |

**주행당 Window가 하나인 데이터 (Old ADA)**: 연속 조건 대신 두 지표의 일치를 쓴다.

| 등급 | 조건 |
|---|---|
| 정상 | 두 지표 모두 p95 이하 |
| 주의 | 한 지표가 p95 초과 |
| 경고 | 한 지표가 정상 최댓값 초과, 또는 두 지표가 p95 초과 |
| 위험 | 두 지표가 정상 최댓값 초과 |

**판정 사유 (`reason`)**: 모든 Window에 등급의 이유를 **센서**, 지표 값, 경계 숫자로 적는다. 경계 이름은 "정상 상한"(p95, 주의·경고 경계)과 "위험 경계"(정상 최댓값)다.

- **센서 구분:** 공개 데이터셋의 센서는 모두 가속도계다(온도·습도 센서 없음). 센서 이름과 설치 위치는 AI① `sensor_info.csv`에서 읽는다 (예: `가속도계 acc01(L/4 부근)`, Ponte Moesa는 `가속도계 acc01(센서 4, 2경간 3/4L)`).
- **두 센서를 합친 지표(AR 거리, 같은 시각 AR 차이):** 등급은 합친 값으로 정하고, 사유에는 **센서별 값**을 함께 적는다. 센서별 값은 같은 방법으로 그 센서의 AR 계수 5개만 써서 계산하고, 경계도 같은 정상 기준으로 따로 정한다. 센서별 값은 설명용이며 등급 계산에 쓰지 않는다.
- **두 센서 사이 지표(1-TAC):** "센서 A–센서 B 전달 관계"로 적는다. 어느 한 센서의 값이 아니라 두 위치 사이의 진동 전달이 정상과 다르다는 뜻이다.

| 등급 | 사유 예시 (HBTA NM 열화본) |
|---|---|
| 정상 | 모든 지표 정상 범위: AR 진동 특성 거리(acc01+acc02 합산, 수직) 3.57 (정상 상한 4.49 이하) — 센서별: 가속도계 acc01(L/4 부근) 1.97 (정상 상한 3.73 이하), 가속도계 acc02(L/2) 1.38 (정상 상한 3.5 이하) / 가속도계 acc01(L/4 부근)–가속도계 acc02(L/2) 전달 관계(1-TAC, 수직) 0.582 (정상 상한 0.715 이하) |
| 경고 | AR 진동 특성 거리(acc01+acc02 합산, 수직) 5.23: 정상 상한 4.49 초과 (위험 경계 6.68 이하) — 센서별: 가속도계 acc01(L/4 부근) 3.76: 정상 상한 3.73 초과 (위험 경계 5.07 이하), 가속도계 acc02(L/2) 1.93 (정상 상한 3.5 이하) / 최근 3개 Window 중 2개가 정상 상한 초과 (경고 조건: 2개 이상) |
| 위험 | AR 진동 특성 거리(acc01+acc02 합산, 수직) 6.94: 위험 경계 6.68 초과 — 센서별: 가속도계 acc01(L/4 부근) 5.12: 위험 경계 5.07 초과, 가속도계 acc02(L/2) 4.25: 위험 경계 3.79 초과 / 가속도계 acc01(L/4 부근)–가속도계 acc02(L/2) 전달 관계(1-TAC, 수직) 0.747: 위험 경계 0.731 초과 / 최근 3개 Window 중 3개가 위험 경계 초과 (위험 조건: 2개 이상) |
| 위험 (지속) | 이번 Window는 모든 지표 정상 범위 / 최근 3개 Window 중 2개가 위험 경계 초과 (위험 조건: 2개 이상) |
| 주의 | … 정상 상한 초과 … / 앞 Window 2개가 없어 지속 여부를 판단할 수 없음 (또는 "지속 아님: 최근 3개 Window 중 1개만 정상 상한 초과") |
| 판정 보류 | 판정 보류: AI① 보류 표시 (진동이 센서 잡음 수준이거나 센서 값 없음) |

Old ADA는 지속 조건 대신 "지표 일치: 정상 상한 초과 n개, 위험 경계 초과 m개"를 적는다. 숫자는 유효숫자 3자리로 적는다.

## 4. 데이터셋별 지표와 정상 기준

판정은 **열화본**(설치할 저가형 센서 조건)으로 하고, 원본은 비교용으로 같은 규칙을 적용한다.

| 데이터셋 | 교량 | 지표 | 정상 기준 Window | Window 간격 |
|---|---|---|---|---|
| Ponte Moesa (`1.1`) | Box | 1-TAC 4-2 z (`tac_4_2_z`), 1-TAC 2-3 z (`tac_2_3_z`) | DS2의 train·val·ai2_calib·session(11/26 저녁, 11/27 낮). 지표별 보류 제외 | 60초 Window, 30초 이동 |
| HBTA NM (`1.1`) | Truss | AR z 거리(v1과 같음: AI① train으로 평균·공분산), 1-TAC z (`tac_a_b_z`) | UDS 두 날짜(9/22, 9/27)의 val·ai2_calib | 10.24초 |
| HBTA SM (`1.2`, `1.2-dev`) | Truss | 같은 시각 AR z 차이 (Truss v2 5절과 같음) | 개발용 3개 조건의 날짜 간 차이 204개 (Truss v2와 같은 값: p95 1.2336, 최댓값 3.5956) | 10.24초 |
| Old ADA (`1.1`) | 점검용 | AR z 거리(표준화 유클리드, train 4회), 1-TAC z | INT 40km/h train 4회(한 회씩 빼고 거리 계산), ai2_calib 3회 | 주행당 1개 |

- **정상 기준에 여러 날을 넣는다.** 개발용 탐색에서 "정상 기준이 하루치면 다른 날의 정상이 이상처럼 보인다"는 결과가 나왔기 때문이다(Truss v2 9절).
- 정상 기준 Window 자체도 등급을 매기지만, 결과표에서는 "정상 기준"으로 따로 표시한다(자기 자신으로 정한 경계라 낮게 나오는 것이 당연함).
- HBTA SM의 정상 기준 측정(조건별 `_01`)은 판정하지 않는다. 개발용 `_02`는 경계를 정하는 데 쓴 데이터라 따로 표시한다.

## 6. 한계

- 등급은 "이상의 확실성"이다. 위험 등급이 손상이 가장 심하다는 뜻이 아니다.
- 이미 본 데이터로 정한 규칙이므로 성능 근거가 아니다. 특히 4절의 지표와 정상 기준 구성은 v1·v2와 탐색 결과를 보고 고른 것이다.
- 지표가 손상에 둔감한 데이터(HBTA SM, Truss v2 AUC 0.60)에서는 손상 Window도 대부분 정상으로 나온다.
- 정상 최댓값은 정상 기준 Window 수가 적으면 불안정하다(Old ADA 7회).
