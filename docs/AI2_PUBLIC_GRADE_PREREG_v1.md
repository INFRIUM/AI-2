# AI② 공개 데이터 등급 검증 사전 등록서 v1

작성일: 2026-11-18 · 상태: **고정 (test 지표 값 확인 전)** · 관련: Issue #13, 합의서 v3 확정본(`INFRIUM/AI-1#3` 6813382749 + 6813474538 + 6813519817), 등급 설계 v0(PR #12)

## 0. 이 문서의 목적과 고정 시점

- 이 문서는 AI①이 전달한 `AI1-public-1.1` 파일로 **AI② 등급을 계산하고 검증하는 규칙**을 test 결과를 보기 전에 고정한다.
- 이 문서를 커밋하고 Push한 뒤에 test 지표 값을 처음 계산한다. 커밋 시각과 문서 SHA-256이 고정 시점의 증거다. 실행 결과 파일에는 이 문서의 SHA-256을 함께 기록한다.
- 결과를 본 뒤 이 문서의 규칙을 바꾸지 않는다. 바꿔야 할 오류가 발견되면 v2 문서로 새로 등록하고, v1 결과와 v2 결과를 둘 다 보고하며 v2에 "결과 열람 후 변경"을 표시한다.

**고정 전에 AI②가 이미 본 것 (공개)**

| 본 것 | 본 범위 |
|---|---|
| AI① v1·v2 판정(`prediction`, `v2_prediction`) | 전체 분할. 등급 계산에 쓰지 않음 |
| AI① v2 Feature `v2_f3` | Ponte Moesa 전체. `AMB_28`(DS3 묶음 A)에서 약 15.0Hz 피크 확인. Box 지표(1-TAC 3–12Hz)는 이 대역을 포함하지 않음 |
| 판정 보류 열, RMS 열, Window 개수 | 전체 분할 |
| AI② 지표(1-TAC, AR) | **test가 아닌 분할(train, val, ai2_calib, Ponte Moesa session)의 값만** 개발용 `--no-test` 실행으로 봄. 여기서 T0·T1, T1 불확실성, Box 세션 차이(원본 2-3 z), HBTA UDS 세션 값, Old ADA 참고선이 나옴. **test 분할의 지표 값은 보지 않음** |

## 2. 판정 보류

| 데이터 | 열화본 (판정) | 원본 (원인 분석·지정 확인) |
|---|---|---|
| Ponte Moesa 주 쌍 | `hold_flag_4_2 = True` 또는 빈 값(센서 4번 없음) | `raw_hold_flag_4_2 = True` 또는 빈 값 |
| Ponte Moesa 세션 쌍 | `hold_flag_2_3 = True` 또는 빈 값 | `raw_hold_flag_2_3 = True` 또는 빈 값 |
| HBTA, Old ADA | `hold_flag_a_b = True` 또는 빈 값 | 원본 보류 열이 없으므로 `raw_rms_acc01_z`, `raw_rms_acc02_z` 중 하나라도 0.00063m/s² 미만이면 보류 |

- 보류 Window는 등급 없이 "판정 보류"로 두고, 오경보율·탐지율·중앙값 계산에서 뺀다. 상태별 보류 비율을 함께 보고한다.
- 보류 판단은 보류 열로만 한다. Feature 값이 남아 있어도 보류 열이 우선한다(전달 파일에서 주 지표 채널 보류 Window의 Feature가 남아 있음을 확인함).
- 지표 값이 빈 Window(예: HBTA 1-TAC 묶음에 포함되지 않은 Window)는 그 지표에서 "판정 불가"로 따로 센다.

## 3. 지표

| 데이터 | 주 지표 (등급 판정) | 비교 지표 (참고) |
|---|---|---|
| Ponte Moesa (Box) | `tac_4_2_z` (1-TAC, 4번·2번 z, 3–12Hz, 60초) | 없음 |
| HBTA (Truss) | **AR 거리**: 열화본 z AR(5) 계수 10개(`acc01_ar1_z`–`acc01_ar5_z`, `acc02_ar1_z`–`acc02_ar5_z`)의 Mahalanobis 거리 | `tac_a_b_z` |
| Old ADA (점검용) | AR 거리(아래 정의)와 `tac_a_b_z`를 둘 다 서술 | - |

**AR 거리 정의**

- 기준 평균 μ와 공분산 Σ는 **AI① train 블록(보류 제외)**에서만 계산한다(합의서 v3 4절). 공분산은 표본 공분산(ddof=1), 역행렬은 `numpy.linalg.pinv`(기본 rcond)로 구한다.
- 거리 d = √((x − μ)ᵀ Σ⁺ (x − μ)). 원본·열화본은 각자의 train 블록으로 따로 계산한다.
- 원본 원인 분석용 y+z 거리(계수 20개)도 같은 방식으로 계산한다.
- Old ADA는 train이 4회뿐이라 공분산을 쓸 수 없으므로 **표준화 유클리드 거리**를 쓴다. d = √(Σ ((xᵢ − μᵢ)/sᵢ)²), μᵢ와 sᵢ(ddof=1)는 train 4회로 계산한다.

두 지표 모두 **값이 클수록 기준 상태와 다르다.**

## 4. 등급과 기대 등급

| 데이터 | 정상 | 주의 | 경고 | 위험 | 참고 |
|---|---|---|---|---|---|
| Ponte Moesa | DS2 | DS3 | DS5 | DS7 | DS6(위험), DS5 `참고` |
| HBTA | UDS | DS3, DS5, DS6 | DS1, DS4, DS7 | DS2, DS8 | - |

## 5. 임계값과 점수

| 임계값 | 점수 | 계산 데이터 | 계산 방법 |
|---|---|---|---|
| T0 | 0 | ai2_calib (보류 제외) | 중앙값 |
| T1 | 25 | ai2_calib (보류 제외) | 95번째 백분위수 (`numpy.percentile`, linear) |
| T2 | 50 | 손상 상태 (아래 교차 검증) | (주의 중앙값 + 경고 중앙값) / 2 |
| T3 | 75 | 손상 상태 | (경고 중앙값 + 위험 중앙값) / 2 |
| T4 | 100 | 손상 상태 | 위험 중앙값 |

- 등급별 중앙값은 그 등급에 속한 상태들의 Window를 모두 합친 뒤의 중앙값이다.
- **점수:** T0–T4 구간마다 선형 변환하고 0–100으로 제한한다.
- **등급:** 지표 ≤ T1 정상, T1 < 지표 ≤ T2 주의, T2 < 지표 ≤ T3 경고, 지표 > T3 위험.
- T1 < T2 < T3 < T4가 성립하지 않으면 그 임계값 묶음으로는 4단계 등급을 만들 수 없다(조건 3 실패로 처리).
- **T1 불확실성:** 모든 데이터셋에 대해 ai2_calib의 최댓값, 상위 3개 값, 95번째 백분위수의 부트스트랩 90% 구간(2000회, 시드 `20261109`)을 함께 보고한다. 이 값들은 T1을 바꾸지 않는다.

**경계 계산과 검증의 분리 (test 재사용 방지)**

| 데이터 | 방법 |
|---|---|
| Ponte Moesa | `cv_group` 두 묶음 교차. A로 T2–T4를 계산해 B를 평가하고, B로 계산해 A를 평가한다. 손상 상태 Window의 등급은 **자기 묶음을 쓰지 않은 임계값**으로 매긴다 |
| HBTA | 상태 제외 검증. 손상 상태 하나를 평가할 때 그 상태를 뺀 나머지 상태로 T2–T4를 계산한다 |
| 공통 | 정상 test는 T0·T1만 쓰므로 손상 데이터와 무관하다. 보고용 "최종 임계값"은 손상 상태 전체로 한 번 더 계산해 함께 적는다 |

## 6. 통과 조건 (열화본으로 판정)

| # | 조건 | Ponte Moesa | HBTA |
|---|---|---|---|
| 1 | 정상 test 오경보율 ≤ 5% (지표 > T1 비율) | DS2 test (작업 중 + 작업 전) | UDS test |
| 2 | 위험 탐지율 ≥ 95% (위험 상태 Window 중 지표 > T1 비율) | DS7 | DS2, DS8 (합산, 상태별도 보고) |
| 3 | 등급 순서: 중앙값이 정상 < 주의 < 경고 < 위험, 그리고 최종 임계값과 모든 교차 묶음에서 T1 < T2 < T3 < T4 | 상태 중앙값 DS2 test < DS3 < DS5 < DS7 | 등급별 중앙값 |
| 4 | 손상 범위 순서 (중앙값) | - | DS2 > DS1, DS4 > DS3, DS7 > DS5, DS7 > DS6 |
| 5 | 상태 일반화: 평가에서 뺀 묶음·상태의 중앙값이 그 상태의 기대 등급 구간에 들어감 | 6개 (DS3·DS5·DS7 × A·B) 모두 | 8개 손상 상태 모두 |

- 조건 2의 "탐지"는 정상이 아닌 등급으로 판정된 것이다(Kamali 2024의 탐지 정의). "위험 등급으로 판정된 비율"은 따로 서술한다.
- 등급 판정은 Window 단위로 한다. 실시간 운영의 등급 변경 규칙(3개 중 2개)은 공개 데이터 검증에 적용하지 않는다.
- **잠정 표시:** 보류 후 Window가 30개 미만인 상태는 그 등급 잠정. Ponte Moesa 정상 test가 30개 미만이면 Box 등급 전체 잠정(합의서 v3 3.6절).

**통과하지 못했을 때 (설계 v0 6절 유지)**

| 실패 | 처리 |
|---|---|
| 조건 3 | 4단계 등급을 출력하지 않는다. 순서가 뒤집힌 인접 등급 쌍을 보고한다. 등급을 합쳐 다시 검증하는 것은 v2 등록으로만 한다 |
| 조건 1 또는 2 | 그 교량은 "기준 대비 이상 여부"도 출력할 수 없다고 기록한다 |
| 조건 4, 5만 실패 | 4단계 등급은 "검증 미완료"로 표시하고 실패 항목을 기록한다 |
| 공통 | 임계값을 맞추기 위해 평가 데이터, 지표, 백분위수를 다시 고르지 않는다 |

모든 조건을 통과해도 `risk_score`, `risk_level`은 API에 연결하지 않는다. 공개 데이터 통과는 HW 모형 실측 검증을 대신하지 않는다(인수인계서 금지 사항).

## 7. 지정 확인 (원본, 합의서 v3)

| 항목 | 규칙 |
|---|---|
| 3.4 작업 영향 | 원본 T1 = 원본 ai2_calib(원본 보류 제외) `tac_4_2_z`의 95번째 백분위수. 작업 전 test(원본 보류 후 n)에서 오경보 수 > 0.05 × n이면 "정상 기준이 작업 진동에 의존"을 한계로 기록하고 Box 결과에 표시. n < 10이면 참고만. 작업 중 test의 오경보율도 보고. 보류 전 결과도 참고로 보고 |
| 3.5 세션 차이 | 원본 `tac_2_3_z`(원본 보류 제외). 세션 차이 = \|중앙값(11/26 저녁) − 중앙값(11/27 낮)\|. 상태 변화 = 중앙값(DS3·DS5·DS7 각각) − 중앙값(11/27 낮). 상태 변화 ≤ 세션 차이면 그 등급 잠정. 비교 Window가 30개 미만이면 참고만. Box 결과에 "세션 차이: 원본으로 확인, 열화본 미검증" 표시 |
| HBTA 원인 분석 | 열화본 z 조건 실패 시 같은 조건을 원본 z(계수 10개), 원본 y+z(계수 20개)로 계산. 열화본 z 실패 + 원본 z 통과 → 센서 잡음. 원본 z 실패 + 원본 y+z 통과 → y축 손실. 원본 y+z도 실패 → 지표 또는 데이터 한계. 원인과 관계없이 열화본 실패는 실패 |
| HBTA 세션 차이 | 열화본 z AR 거리, `UDS_01` vs `UDS_02`(ai2_calib + test) 중앙값 차이를 서술. 두 UDS 합산이 판정 기준이고, `UDS_01`만 쓴 T1·오경보율은 참고 |
| HBTA 조건 표시 | `train_passing`, 온도(DS3·DS4 약 21–22°C)를 상태별로 함께 표시 |

## 8. Old ADA (점검용, 통과 판정 없음)

- 지표: AR 거리(표준화 유클리드)와 `tac_a_b_z`. 주행마다 1개 Window.
- 보고: 주행별 값, 상태별 중앙값과 순서, 정상 test(40km/h 3회) 중 참고선 초과 수. 참고선은 AI② 기준(ai2_calib) 3회의 최댓값이다.
- `속도 영향 확인용 (참고)` 주행(30·50km/h)은 따로 보고. `RCV`는 오경보 계산에서 제외. 원본·열화본 모두 보고하되 열화본에는 "단위 m/s² 간접 추정, gal이면 전부 판정 보류"를 표시.

## 9. 함께 보고할 한계

- Ponte Moesa Window는 60초이며 서로 겹친다. HBTA 1-TAC는 Window 3개가 같은 값을 공유한다. Window는 독립 표본이 아니므로 측정(실험 블록) 단위 중앙값도 함께 보고한다.
- Ponte Moesa DS7 두 묶음은 같은 측정(`AMB_47`)이라 독립 검증이 아니다.
- HBTA 손상 상태는 상태마다 측정이 하나라, 상태 차이와 측정 시점 차이를 구분할 수 없다.
- AI① v2 Feature와 AI② 지표는 두 센서 응답 비와 스펙트럼 정보를 일부 공유한다. 같은 결론을 독립 근거 두 개로 쓰지 않는다.

## 10. 실행과 재현

```bash
.venv/bin/python -m src.public_grade.run --data-dir data/raw/ai1_public_1.1
```

- `--no-test`: test 분할을 빼고 실행한다(개발용). 사전 등록 전 디버깅은 이 옵션과 합성 데이터 단위 테스트로만 했다.
- 출력: 터미널 요약, `results/public_grade/summary.json`(요약 수치, 입력 MD5, 코드 커밋, 이 문서의 SHA-256), `data/processed/public_grade/window_grades.csv`(Window별 등급, git 제외).
