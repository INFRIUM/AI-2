# AI② Truss 공개 데이터 평가 결론

작성일: 2026-11-20 (11-22 v4 Vänersborg 추가) · 관련: #13, #16, #18, #19, #23 · 대상 데이터: HBTA(NM·SM), Old ADA (모두 강철 트러스교), v4 Vänersborg (개폐식 트러스교)·LUMO (격자 철탑)

## 0. 결론

> **Truss는 공개 데이터로 "판정"과 "내부 평가"까지 마쳤고, "검증"은 새 데이터가 없어 할 수 없다.**
> **판정(등급 출력)은 된다.** 모든 Window에 정상/주의/경고/위험 등급과 판정 사유가 나온다. 다만 **그 판정의 정확도가 통과 기준에 못 미친다.**
> 내부 평가에서 어떤 방법·설정도 열화본(HW 센서 조건) 기준 **오경보 ≤ 5%, 위험 탐지 ≥ 95%를 동시에 넘지 못했다.**
> 원본(고급 센서)에는 손상 신호가 있지만, HW 센서 조건에서는 그 신호의 핵심인 **횡방향 진동 정보가 사라진다.**

**통과 기준 (두 가지를 동시에 만족해야 통과)**

| 기준 | 뜻 |
|---|---|
| 오경보 ≤ 5% | 정상인 교량을 이상하다고 잘못 판정하는 비율이 5% 이하 |
| 위험 탐지 ≥ 95% | 가장 심한 손상을 이상으로 잡아내는 비율이 95% 이상 |

하나만 좋아서는 안 된다. 모든 Window를 "이상"이라고 하면 탐지는 100%지만 오경보도 100%가 된다. 이 문서에서 "실패", "미달"은 판정이 안 됐다는 뜻이 아니라 **이 기준을 넘지 못했다**는 뜻이다.

> **v4 (새로 받은 실제 구조물 데이터, 2026-11-22 추가):** 보조 평가 Vänersborg(개폐식 트러스교 실제 파단)는 1회 실행에서 **통과 못 함 (잠정)**: 오경보 6.1%, 위험 탐지 6.6%, AUC 0.50. 주 평가 LUMO(격자 철탑)는 AI① 처리 중이다. 교통 진동 조건의 트러스교 손상 탐지는 검증 데이터 없음.

- API의 `risk_score`, `risk_level`은 계속 `null`이다.
- Truss 등급은 "검증 아님, 공개 데이터 내부 평가 기준 미달"을 함께 표시할 때만 보여 준다 (5절).
- 이후로 같은 데이터에 맞춰 Truss 규칙을 다듬지 않는다 (6절).

## 1. 평가 단계

| 단계 | 뜻 | Truss 상태 |
|---|---|---|
| 판정 | 모든 Window에 등급과 판정 사유를 낸다 | ✅ 완료 (규칙 v3, XGBoost) |
| 내부 평가 | 이미 본 데이터를 측정 단위로 나눠 교차 평가한다. "이 데이터 안에서의 최선의 추정치" | ✅ 완료 (2–4절) |
| 검증 | 아직 보지 않은 데이터로 사전 등록 후 1회 평가한다 | HBTA·Old ADA는 ❌ 불가 (HBTA 50개 측정을 모두 썼고 Old ADA도 이미 봤다). 새 데이터로 v4 진행 중: Vänersborg 통과 못 함 (잠정), LUMO 처리 중 |

## 2. 사용한 데이터

| 데이터 | 진동 종류 | 구성 | 사용 |
|---|---|---|---|
| HBTA NM (`AI1-public-1.1`) | 노이즈 가진 (무작위) | 위치 P2·수직 가진, 정상 2개(9/22, 9/27), 손상 DS1–DS8 각 1개 | v1 검증, 탐색, v3, XGBoost |
| HBTA SM (`AI1-public-1.2`, `1.2-dev`) | 스윕 가진 (한 주파수씩) | 4개 조건 × (정상 2개 + 손상 8개) | v2 검증, 탐색, v3, XGBoost |
| Old ADA (`AI1-public-1.1`) | 차량 통과 후 자유 감쇠 | 주행 68회: 정상 26 (40km/h 10, 30·50km/h 16), DMG1 12, DMG2 10, DMG3 10, RCV 10 | v1 서술, v3, XGBoost |

열화본 = AI①이 원본에 HW 센서(LIS2DW12) 잡음·14bit 해상도·±2g 범위를 적용한 데이터. **판단 기준은 열화본**이고 원본은 원인 비교용이다.

## 4. 원인

| 원인 | 근거 |
|---|---|
| ① **HW 센서 조건에서 횡방향 정보 소실** | HBTA NM 원본 XGBoost AUC 0.93, 열화본 0.67. 원본 모델의 가장 중요한 특징은 acc01 횡방향(y) AR 계수인데, 열화본에서는 y축 진동(RMS 0.0016–0.002m/s²)이 보류 기준(0.0058)보다 작아 y축 AR의 99.8%가 보류된다. 잡음을 다시 생성해도 되살아나지 않는다(AI① 확인) |
| ② **열화본 모델이 날짜를 이용** | HBTA NM에서 학습 정상을 손상과 같은 날(9/27)로 두어 날짜를 이용할 수 없게 하면, 열화본은 오경보 3%, **손상 탐지 23%**. 날짜를 이용할 수 있으면 오경보 41%, 탐지 61%. 원본은 두 경우 모두 AUC 0.93–0.94 |
| ③ **정상 데이터가 실제 정상의 변동을 담지 못함** | HBTA 정상 2일뿐 (하루치로 학습하면 다른 날 정상을 손상으로 판정). Old ADA 열화본 오경보는 대부분 속도가 다른 정상 주행에서 나옴 (40km/h 1/10, 30km/h 6/11, 50km/h 4/5) |
| ④ **스윕 가진은 이 방식에 맞지 않음** | HBTA SM은 원본도 AUC 0.58. 10초 Window 안에서 교량이 한 주파수로만 흔들려 지표가 가진 주파수를 담는다 |

참고: Old ADA(차량 통과)는 진동이 커서(약 0.2m/s²) 열화본과 원본 차이가 거의 없다(AUC 0.70 vs 0.71). **진동이 충분히 크면 HW 센서 잡음은 큰 문제가 아니다.**

## 5. Truss 출력 방식 (제안)

| 항목 | 내용 |
|---|---|
| 판정 규칙 | **규칙 v3** (`docs/AI2_GRADE_RULE_v3.md`). 정상 데이터만으로 경계를 정하므로 손상 예시가 없는 새 트러스교에도 같은 방식으로 적용 가능. XGBoost는 교량마다 손상 예시가 필요해 참고용 |
| 출력 내용 | 등급(정상/주의/경고/위험), 판정 사유(센서 이름·위치, 값, 경계 숫자, 지속 여부) |
| 반드시 함께 표시 | "검증 아님. 공개 데이터 내부 평가에서 오경보·탐지 기준 미달. 등급은 정상 기준과 다르다는 확실성이며 손상 정도가 아님" |
| API | `risk_score`, `risk_level`에 연결하지 않음 (인수인계서 금지 사항) |

## 6. 이후 원칙

- HBTA, Old ADA에 맞춰 Truss 규칙이나 모델을 더 다듬지 않는다. 이미 본 데이터에 맞출수록 숫자는 좋아지지만 근거는 약해진다.
- 새 Truss 데이터(손상 시험, 여러 날 정상, NM형 진동, 아직 안 본 데이터)가 생기면, 지금 방법을 사전 등록하고 1회 검증한다.
- 노력은 검증 데이터(Z24)가 남아 있는 Box에 집중한다. 단, Box 방법은 Truss 결과로 정하지 않고 Z24 정상 데이터(손상 시험 전 상시 계측)로 따로 정한다. Ponte Moesa는 정상 상태가 없어 정상 판별·등급 평가에 쓰지 않는다.
